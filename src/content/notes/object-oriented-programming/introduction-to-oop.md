Object-Oriented Programming (OOP) organizes software around objects instead of only functions.

An object represents a real-world entity and combines:

- Data: properties or attributes.
- Behavior: methods or functions.

## Why OOP Exists

Procedural programming divides code into functions that operate on data. As systems grow, shared data becomes hard to control, features become harder to add, and changes in one place can break unrelated code.

OOP groups related data and behavior into classes and objects, making code more modular and easier to maintain.

## Goals of OOP

- Modularity: divide systems into independent objects.
- Reuse: reuse classes and behavior.
- Maintainability: isolate change.
- Scalability: grow systems with clearer boundaries.
- Safety: protect data through controlled access.

## Procedural Programming vs OOP

| Procedural Programming | Object-Oriented Programming |
| --- | --- |
| Focuses on functions | Focuses on objects |
| Data and functions are separate | Data and methods stay together |
| Shared/global data is common | Data is encapsulated inside objects |
| Reuse is limited | Reuse through composition, interfaces, and inheritance |
| Changes can spread widely | Objects reduce impact of change |

## Car Analogy

A car has data:

- Brand.
- Color.
- Speed.
- Fuel level.

It also has behavior:

- Start.
- Accelerate.
- Brake.
- Stop.

In OOP, the car object owns both its state and the operations that work on that state.

## Where OOP Is Used

- Backend applications.
- Enterprise software.
- Android development.
- Desktop applications.
- Game development.
- GUI applications.

Frameworks like Spring Boot, Hibernate, ASP.NET, and many large application architectures rely heavily on OOP concepts.

## Interview Notes

- OOP is a programming paradigm based on objects.
- Objects combine state and behavior.
- OOP helps build large, maintainable systems.
- Classes act as blueprints; objects are created from those blueprints.
