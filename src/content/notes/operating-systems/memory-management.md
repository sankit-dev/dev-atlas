## Physical memory

Physical memory is the actual RAM installed in the computer. It is a hardware resource used to store data and instructions that are currently being executed.

Example:

```plain text
Laptop RAM = 16 GB
```

---

## Virtual memory

Virtual memory is a logical memory space created by the operating system.

It gives each process the illusion of having its own large, continuous memory space, even if available physical RAM is limited.

When RAM is full, the operating system can temporarily move inactive data to disk, using swap space or a page file, and load it back into RAM when needed.

---

## Why virtual memory?

- Allows programs to use more memory than available physical RAM.
- Provides memory isolation between processes.
- Prevents one process from accessing another process's memory.
- Simplifies memory management for applications.

---

## Physical memory vs virtual memory

| Physical Memory | Virtual Memory |
| --- | --- |
| Actual RAM installed in the system. | Logical memory space created by the operating system. |
| Hardware resource. | OS-managed abstraction. |
| Limited by installed RAM. | Can appear larger than physical RAM. |
| Faster access. | May be slower if data needs to be fetched from disk. |

Important points:

- Every process gets its own virtual address space.
- A process does not access RAM directly.
- The operating system maps virtual addresses to physical memory.
- Allocating 4 GB of virtual memory does not mean 4 GB of RAM is immediately used.
- Physical RAM is allocated as the process actually accesses virtual memory.

---

## Paging

Paging is a memory management technique in which both virtual memory and physical memory are divided into fixed-size blocks.

- Blocks in virtual memory are called pages.
- Blocks in physical memory are called frames.
- The operating system maps pages to frames.

Suppose a process has 16 KB of virtual memory and the page size is 4 KB.

Virtual memory:

```plain text
Page 0 (4 KB)
Page 1 (4 KB)
Page 2 (4 KB)
Page 3 (4 KB)
```

RAM is also divided into 4 KB frames.

The operating system may store pages like this:

```plain text
Page 0 -> Frame 3
Page 1 -> Frame 0
Page 2 -> Frame 5
Page 3 -> Frame 2
```

Pages do not need to be stored next to each other in RAM. They can be placed wherever there is a free frame.

---

## Why paging is useful

Without paging, a process would need one large continuous block of RAM. That can be difficult when memory is fragmented.

With paging:

- The operating system finds free frames.
- It places each page wherever space is available.
- The process still thinks its memory is continuous.

Key points:

- Virtual memory is divided into pages.
- Physical memory is divided into frames.
- Pages and frames are the same size.
- Pages can be stored anywhere in RAM.

---

## Page table

The page table is a data structure maintained by the operating system that stores the mapping between a process's virtual pages and physical frames.

It tells the operating system which page is stored in which frame.

Example:

| Page Number | Frame Number |
| --- | --- |
| 0 | 7 |
| 1 | 2 |
| 2 | 10 |
| 3 | 5 |

When the CPU asks for page 2, the operating system checks:

```plain text
Page 2 -> Frame 10
```

Now it knows where the data is in RAM.

---

## Virtual address vs physical address

### Virtual address

The virtual address is generated by the CPU.

Example:

```plain text
Page 2, Offset 100
```

The process thinks its data is on page 2. It does not know where that data actually is in RAM.

### Physical address

The physical address is the actual location in RAM after the operating system translates the virtual address.

Example:

```plain text
Frame 10, Offset 100
```

Only the page number changes to a frame number. The offset remains the same.

---

## Address translation

Suppose the CPU wants to read:

```plain text
Page 2
Offset 100
```

Step 1: look in the page table.

```plain text
Page 2 -> Frame 10
```

Step 2: replace the page number.

```plain text
Frame 10
Offset 100
```

This process is called address translation.

The offset stays the same because the data is the same distance from the beginning of the page or frame.

---

## TLB

TLB means Translation Lookaside Buffer.

Every time the CPU accesses memory, it first checks the page table to find the corresponding frame. But the page table is itself stored in RAM.

Without a TLB, every memory access may require:

1. Reading the page table from RAM.
2. Reading the actual data from RAM.

A TLB is a small, high-speed cache that stores recently used page table entries.

---

## How TLB works

```plain text
CPU
 |
 v
TLB
 |-- Found (TLB Hit) -> Read data from RAM
 |
 |-- Not Found (TLB Miss)
          |
          v
     Page Table in RAM
          |
          v
     Update TLB
          |
          v
     Read data from RAM
```

### TLB hit

If `Page 2 -> Frame 10` is already stored in the TLB, the CPU immediately gets `Frame 10` and reads the data from RAM.

Only one RAM access is needed.

### TLB miss

If the mapping is not in the TLB, the CPU checks the page table, finds the frame, stores the mapping in the TLB, and then reads the data.

---

## Why is a TLB needed?

Because the page table is stored in RAM. Without a TLB, every memory access would require an additional RAM access to read the page table. The TLB caches recent mappings and improves performance.

---

## Page fault

A page fault occurs when a process tries to access a page that is not currently loaded in physical memory.

The operating system loads the required page from disk into RAM.

Example:

```plain text
Page 0 -> Frame 3
Page 1 -> Frame 8
Page 2 -> on disk
Page 3 -> on disk
```

If the process tries to access page 2, the operating system finds that page 2 is not in RAM. A page fault occurs.

---

## What happens during a page fault?

1. CPU requests page 2.
2. The operating system checks the page table.
3. Page 2 is not present in RAM.
4. A page fault is raised.
5. The operating system loads page 2 from disk into a free frame in RAM.
6. The page table is updated.
7. The program continues execution.

Flow:

```plain text
CPU
 |
 v
Needs Page 2
 |
 v
Page not in RAM
 |
 v
Page Fault
 |
 v
Load Page from Disk
 |
 v
Update Page Table
 |
 v
Resume Program
```

---

## Why is a page fault slow?

RAM is much faster than disk.

Approximate speeds:

- RAM: nanoseconds.
- Disk: microseconds to milliseconds.

Since the operating system has to read the page from disk, a page fault is much slower than a normal memory access.

---

## Demand paging

Demand paging means the operating system does not load all pages into RAM immediately.

Instead, it loads a page only when the process actually needs it.

Example:

```plain text
Process has 100 pages
Initially 10 pages are loaded
Remaining 90 pages stay on disk until needed
```

This saves RAM and allows more processes to run simultaneously.

---

## Quick revision

- Physical memory is actual RAM.
- Virtual memory is the logical address space given to each process.
- Paging divides virtual memory into pages and RAM into frames.
- Page tables map pages to frames.
- A TLB caches recent page table entries.
- A page fault happens when a required page is not in RAM.
- Demand paging loads pages only when needed.

---

## Interview tip

> A page fault is not always an error. It is a normal operating system event that tells the OS to load the required page from disk into RAM.
